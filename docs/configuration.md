# Configuration

Every setting of a Codehaven instance, what it does, its default and whether you must set it. There are three layers: the env file that the deploy scripts read, the server's own settings (`codehaven.toml` keys, which the env file reaches only in part), and the runner's settings file.

## Three places settings live

| Place | What lives there | How you change it |
| --- | --- | --- |
| The env file (`.env`) | Everything the deploy scripts and the compose file need: addresses, directories, the proxy, backups, and a few switches | Edit the file, then run `sudo bash deploy/prod/up.sh` |
| The server's own settings (`codehaven.toml` keys) | Everything else about the server: mail, CI limits, rate limits, Pages limits, the connector's allowed hosts | `CODEHAVEN__SECTION__KEY` environment variables, or a config file. See "Settings the env file does not carry" |
| The Site admin pages | Switches an admin changes while the server runs: public repositories, which actions workflows may use, the browser editor and terminal, Pages full mode, invites, runners, users | Site admin in the avatar menu (admin accounts with two-factor on) |

The name rule from a `codehaven.toml` key to an environment variable: upper case, two underscores between the parts, prefix `CODEHAVEN__`. So `ci.log_retention_days` is `CODEHAVEN__CI__LOG_RETENTION_DAYS` and `mail.smtp.host` is `CODEHAVEN__MAIL__SMTP__HOST`. The server reads a config file from `/etc/codehaven/codehaven.toml` inside its container (or the path in `CODEHAVEN_CONFIG`), and the environment variables win over it. The stock compose file mounts no config file, so use environment variables through an extra compose file, or mount your own file the same way.

## The env file

The deploy scripts read one file. Copy `.env.example` to `.env` in the checkout, or keep it next to the checkout as `../codehaven.env`, or point `CH_ENV_FILE` at it. Use one place only: with two candidates the scripts stop and say so.

- Lines are `KEY=value` with an upper case name (no `export`). Blank lines and lines starting with `#` are skipped. A value may be wrapped in one pair of single or double quotes, which are removed. Nothing else is interpreted: there are no escapes, and a `#` later on a line is part of the value, so put comments on their own line. Use single quotes around a JSON list so its double quotes survive: `CODEHAVEN_TRUSTED_PROXIES='["10.20.16.0/24"]'`.
- The file is parsed, never run, so a value cannot hold a command.
- A variable already set in the shell wins over the file.
- The file holds no secrets. The database password is generated by `setup.sh` into `CODEHAVEN_SECRETS_DIR`, and the server makes its own master key.
- A required setting that is missing stops the script with its name. Nothing falls back to a guess.

"Required" below means a script or the compose file stops without it. The default column is what applies when you leave a setting out.

### The instance

| Setting | Default | Required | What it does |
| --- | --- | --- | --- |
| `CODEHAVEN_PROJECT` | none (`.env.example` says `codehaven`) | Yes | The compose project name. Containers, networks and volumes are named after it, and so are backup archives. To run two instances on one host, give each its own project, directories and ports |
| `CODEHAVEN_EXTERNAL_URL` | none | Yes | The address people open, with the scheme and no path and no trailing slash: `https://code.example.com`. The server stops at start with a plain message if it is empty, has a path, or does not start with `http://` or `https://`. Links, clone addresses, the origin check on every form, the cookie name, HSTS and passkeys all follow it. Use `https` unless this is a trial on loopback |
| `CODEHAVEN_NAME` | `Codehaven` | No | The name shown on the sign-in page |
| `CODEHAVEN_LOG_FORMAT` | `json` | No | `json` or `pretty` |
| `CODEHAVEN_TAG` | the first 12 characters of the checkout's commit id | No | The image tag the instance runs. Every commit gets its own tag, so earlier images stay on the host for rollback. `up.sh <tag>` overrides it for one run |

### Where things live on this host

| Setting | Default | Required | What it does |
| --- | --- | --- | --- |
| `CODEHAVEN_DATA_DIR` | none | Yes | The instance's data. `setup.sh` makes `postgres`, `git`, `blobs`, `logs`, `secrets` and `dind` under it. It needs 20 GB free. `git`, `blobs`, `logs` and `secrets` belong to uid 10001, the server's user |
| `CODEHAVEN_SECRETS_DIR` | none | Yes | Holds `pg_password` and `database_url`, written once by `setup.sh` and never printed. Owned by root with group 10001, mode 750, files 440 |
| `CODEHAVEN_BACKUP_DIR` | none | Yes | Where backups go. It must be outside the checkout (the scripts refuse otherwise) and is made mode 700. Treat it like the instance itself: archives hold the master key |
| `CODEHAVEN_BUILD_ROOT` | none | Yes, for `up.sh` | Holds the build slot locks, the "rolled back" mark (`run/<project>.rolled-back`), the deploy smoke log (`run/up-smoke.log`) and the copy of `deploy/` that the backup timer runs |

You do not create these directories. `setup.sh` makes the data and secrets directories (and parents), and `up.sh`, `backup.sh` and the timer make the backup directory and `CODEHAVEN_BUILD_ROOT` as needed, all as root. A typical block, with everything under one root:

```sh
CODEHAVEN_DATA_DIR=/srv/codehaven/data
CODEHAVEN_SECRETS_DIR=/srv/codehaven/secrets
CODEHAVEN_BACKUP_DIR=/srv/codehaven/backups
CODEHAVEN_BUILD_ROOT=/srv/codehaven
```

### Ports

| Setting | Default | Required | What it does |
| --- | --- | --- | --- |
| `CODEHAVEN_HTTP_BIND` | none (`.env.example` says `127.0.0.1:3200`) | Yes | The host address and port the web server is published on. Port 3200 inside the container. Loopback unless you want it reachable directly. `up.sh` stops if a loopback bind turns out reachable from outside |
| `CODEHAVEN_SSH_BIND` | none (`127.0.0.1:2222`) | Yes | The host address and port for git over SSH. Port 2222 inside the container. Use `0.0.0.0:2222` to let other machines in. Port 22 is usually the host's own sshd, so Codehaven does not take it |
| `CODEHAVEN_SSH_EXTERNAL` | none (`127.0.0.1:2222`) | Yes | The host, and normally the port, that the pages tell people to clone from, as `host:port`, for example `code.example.com:2222`. A value with no port means port 22. Port 22 gives `git@host:owner/repo.git`; any other port gives `ssh://git@host:port/owner/repo.git`. It only changes what is displayed: `CODEHAVEN_SSH_BIND` decides where the server listens. When it names a loopback or private address, the repository page says SSH works only through a tunnel |

### The proxy in front

| Setting | Default | Required | What it does |
| --- | --- | --- | --- |
| `CODEHAVEN_PROXY` | none (`.env.example` says `none`) | Yes | `none`, `network` or `caddy`. See "The proxy" below |
| `CODEHAVEN_TRUSTED_PROXIES` | none | Yes | A JSON list of the networks your proxy reaches the server from, for example `'["10.20.16.0/24"]'`. Only a peer inside one may set `X-Forwarded-For` and `X-Forwarded-Proto`. `[]` when nothing sits in front. A list holding `0.0.0.0/0` or `::/0` is refused at start, because anyone could then fake their address |
| `CODEHAVEN_TRUSTED_PROXY_HOSTS` | `[]` | No | Instead of a network, the proxy's container name on a shared Docker network, such as `'["caddy"]'`. Only the addresses that name has are trusted, looked up again every 30 seconds. Plain lowercase names only |
| `CODEHAVEN_PROXY_NETWORK` | none | With `network` | The name of an existing Docker network your proxy is on. `setup.sh` stops if it does not exist |
| `CODEHAVEN_PROXY_ALIAS` | none | With `network` | The name the server takes on that network. Your proxy sends to `<alias>:3200`. `setup.sh` stops if another container already has that alias there |
| `CODEHAVEN_SITE_HOST` | none | With `caddy` | The host name Caddy gets a certificate for. It must already point at this machine |
| `CODEHAVEN_EDGE_SUBNET` | none | With `caddy` | A free private network in CIDR form, a /24 such as `10.20.16.0/24`, for the link between Caddy and the server. Pick a range that `ip route` and `docker network ls` do not already use. The same value goes into `CODEHAVEN_TRUSTED_PROXIES` as `'["10.20.16.0/24"]'` |

### Backups

| Setting | Default | Required | What it does |
| --- | --- | --- | --- |
| `CODEHAVEN_BACKUP_KEEP_DAILY` | `7` | No | Days whose newest archive the daily schedule keeps |
| `CODEHAVEN_BACKUP_KEEP_WEEKLY` | `4` | No | ISO weeks whose newest archive the daily schedule keeps |
| `CODEHAVEN_BACKUP_MIN_FREE_MB` | `2048` | No | Free space the backup disk must have, or the daily run skips itself and says so in the log. The run also needs three times the newest archive and twice the data it copies |
| `CODEHAVEN_BACKUP_OFFSITE` | empty | No | An encrypted copy of each daily archive. `rsync:<destination>` or `s3://<bucket>/<prefix>`. Nothing is sent while it is empty |
| `CODEHAVEN_BACKUP_OFFSITE_ENDPOINT` | empty | No | An S3-compatible endpoint URL for the `s3://` form, passed to the `aws` CLI as `--endpoint-url` |
| `CODEHAVEN_BACKUP_OFFSITE_PASSPHRASE_FILE` | empty | With an off-site copy | A root-only file (mode 600 or 400) holding the passphrase. The env file holds no secrets, so the passphrase lives in that file. S3 credentials stay in the `aws` CLI's own config |

Backups are covered in [Running an instance](operations.md).

### Features that are off until you turn them on

| Setting | Default | What it does |
| --- | --- | --- |
| `CODEHAVEN_MCP_ENABLED` | `false` | `true` turns on the Claude connector at `/mcp`. It needs an `https` `CODEHAVEN_EXTERNAL_URL` (plain `http` only for `localhost`) or the server refuses to start. See [The Claude connector](connector.md) |
| `CODEHAVEN_DOCS_URL` | `https://aaron777collins.github.io/codehaven-forge/` | Where the Docs link in the page footer and account menu points. Set it to your own address to host the docs yourself. Empty turns the link off. It must be an absolute `http` or `https` address |
| `CODEHAVEN_PAGES_HOST` | empty | A host name for Pages sites, such as `pages.example.com`. It must differ from the app's host and must not be a parent of it, or the server refuses to start. See [Pages](pages.md) |

### CI and building

| Setting | Default | What it does |
| --- | --- | --- |
| `CODEHAVEN_RUNNER_NAME` | none (`.env.example` says `runner-1`) | The name `ci-up.sh register` uses when you give none. Needed only then |
| `CODEHAVEN_BUILDX_BUILDER` | unset | The buildx builder to use. Unset uses Docker's default |
| `CODEHAVEN_BUILD_CPUS` | the number of CPUs, at most 3 | CPUs one build may use |
| `CODEHAVEN_BUILD_MEMORY` | `8g` | Memory one build may use |
| `CODEHAVEN_BUILD_SLOTS` | `3` | Builds that may run at once (not in `.env.example`) |
| `CODEHAVEN_DISK_PATHS` | `/` | Space separated paths whose disks are watched before a build or `setup.sh` |
| `CODEHAVEN_DISK_LIMIT` | `85` | The percent full at which builds and `setup.sh` stop |
| `CODEHAVEN_CI_BUILDER` | unset | Set to `1` for `ci-up.sh` to load the builder image into the runner's daemon, so Codehaven can build itself. A few GiB |

### Used by the scripts, not set in the file

| Setting | Default | What it does |
| --- | --- | --- |
| `CODEHAVEN_DEPLOY_WAIT` | `300` | Seconds `up.sh` waits for the server to be healthy. Generous, because a long migration is not healthy until it finishes |
| `CODEHAVEN_SMOKE_URL` | `http://` plus `CODEHAVEN_HTTP_BIND` | The address `up.sh` runs the smoke check against |
| `CODEHAVEN_NO_MIGRATE` | unset | `1` starts the server without applying migrations. For a rollback to an older version (see [Running an instance](operations.md)) |
| `CODEHAVEN_COMPOSE_EXTRA` | unset | The absolute path of an extra compose file merged after the stock ones. For what the stock files leave open: fixed subnets, extra server settings, resource limits |
| `CH_ENV_FILE` | unset | The env file to use instead of `.env` |
| `HAVEN_RUNNER_TOKEN` | none | The registration token for `ci-up.sh register`. Passed in the environment so it stays out of the process list |

### Only for test stacks

`CODEHAVEN_E2E_SUBNET`, `CODEHAVEN_SHOTS_RUNNERS_SUBNET`, `CODEHAVEN_SHOTS_NODE_MODULES`, `CODEHAVEN_DEV_PROJECT` and `CH_HOST` with `CH_REMOTE_ROOT` belong to `make e2e`, the screenshot run and building on another host over ssh. You do not need them to run an instance.

## The proxy

| `CODEHAVEN_PROXY` | What you get |
| --- | --- |
| `none` | The web server and ssh on the addresses in `CODEHAVEN_HTTP_BIND` and `CODEHAVEN_SSH_BIND`, loopback by default. No TLS. For a trial, or for a proxy that runs on the host |
| `network` | The server joins the existing Docker network `CODEHAVEN_PROXY_NETWORK` under the alias `CODEHAVEN_PROXY_ALIAS`. Your proxy sends to `<alias>:3200`, and you add that site yourself. Codehaven changes nothing in your proxy |
| `caddy` | A Caddy in the same project gets the certificate for `CODEHAVEN_SITE_HOST` and sends to the server. It publishes ports 80 and 443, so the name must point at this machine and both ports must be free |

Whatever you use, your proxy must send every path to the server (including `/.well-known/` and `/oauth/`), remove any `Remote-User` style header the client sends, and not buffer responses, or live CI logs stall. Codehaven reads no identity header, so a proxy cannot sign anyone in by accident. `deploy/Caddyfile.example` is a working example, with the extra site for Pages as a comment.

## Settings the env file does not carry

The compose file passes a fixed set of variables to the server: the external URL, name, trusted proxies, SSH address, log format, the connector switch, the Pages host and the webhook block list. Every other server setting keeps its default, and the stock compose file has no place to change it. That includes outgoing mail, which is therefore off until you do the following.

The server reads `CODEHAVEN__SECTION__KEY` environment variables (two underscores between parts) over an optional config file at `/etc/codehaven/codehaven.toml`. To set one, write an extra compose file and point `CODEHAVEN_COMPOSE_EXTRA` at it. For mail:

```yaml
# /srv/codehaven/compose.extra.yml
services:
  server:
    environment:
      CODEHAVEN__MAIL__SMTP__HOST: smtp.example.com
      CODEHAVEN__MAIL__SMTP__PORT: "587"
      CODEHAVEN__MAIL__SMTP__USERNAME: codehaven
      CODEHAVEN__MAIL__SMTP__PASSWORD_FILE: /run/secrets/smtp_password
      CODEHAVEN__MAIL__SMTP__FROM: "Codehaven <code@example.com>"
    volumes:
      - /srv/codehaven/secrets/smtp_password:/run/secrets/smtp_password:ro
```

The password file must be readable by uid 10001, for example `chown root:10001` and mode 440. Then add `CODEHAVEN_COMPOSE_EXTRA=/srv/codehaven/compose.extra.yml` to the env file and run `sudo bash deploy/prod/up.sh`. The same file can hold the fixed subnets described in [Troubleshooting](troubleshooting.md).

### Server settings

`deploy/codehaven.example.toml` shows the file form. In the environment, `ci.log_retention_days` is `CODEHAVEN__CI__LOG_RETENTION_DAYS`, and so on.

| Key | Default | What it does |
| --- | --- | --- |
| `server.name` | `Codehaven` | Name on the sign-in page. Set by `CODEHAVEN_NAME` |
| `server.bind` | `0.0.0.0:3200` | The public listener inside the container. Everything behind the gate |
| `server.internal_bind` | `127.0.0.1:9300` | Serves `/readyz` and `/metrics`. It must be a loopback address, or the server refuses to start |
| `server.external_url` | none | See `CODEHAVEN_EXTERNAL_URL` |
| `http.trusted_proxies`, `http.trusted_proxy_hosts` | `[]` | See the proxy settings above |
| `http.request_timeout_secs` | `60` | How long an ordinary request may take |
| `http.upload_idle_secs` | `60` | A release file upload is not cut off at the request time, but the sender may be silent this long between two chunks at most |
| `database.url_file` | set by compose | A file holding the database URL, so the password stays out of the environment. `database.url` also works |
| `database.max_connections` | `20` | The database pool size |
| `storage.data_dir` | `/data` | Holds `git/`, `blobs/`, `logs/` and `secrets/` |
| `storage.min_free_gib` | `10` | GiB that uploads and pushes always leave free on the data disk. An artifact, cache, release file, image layer or push that would go below it is refused, so the database keeps room to work |
| `ssh.enabled` | `true` | `false` turns git over SSH off and hides the SSH clone address |
| `ssh.bind` | `0.0.0.0:2222` | The SSH listener inside the container |
| `ssh.external` | `127.0.0.1:2222` | What the pages show. Set by `CODEHAVEN_SSH_EXTERNAL` |
| `invites.org_owners_can_invite` | `false` | When `true`, an owner of an organization may make invites into that organization through the REST API (`POST /api/v3/admin/invites` with an `org_id`). The web pages offer invites to site admins only |
| `invites.default_expiry_hours` | `168` | Default invite lifetime (7 days) |
| `invites.min_expiry_hours`, `invites.max_expiry_hours` | `1`, `720` | The limits for an invite's lifetime (1 hour to 30 days) |
| `mail.smtp.host`, `port`, `username`, `password_file`, `from`, `tls` | no mail | Outgoing mail. `tls` is `starttls` (default), `tls` for port 465, or `none`, accepted only for a relay on `localhost`, `127.0.0.1` or `::1`. A `username` needs a `password_file` |
| `webhooks.allow_private` | `false` | Lets webhooks reach private and loopback addresses. For test stacks only: `first-admin.sh` refuses to run while it is on |
| `webhooks.blocked_ips` | set by `compose.sh` | The host's own public addresses, which webhooks may never reach |
| `imports.allow_private` | `false` | Lets "Import a repository" reach private addresses and plain `http`. Off by default |
| `ci.log_retention_days` | `90` | How long job logs are kept |
| `ci.registration_token_ttl_minutes` | `60` | How long a runner registration token lasts |
| `ci.queue_timeout_minutes` | `1440` | A queued job that no runner takes in this long fails as timed out |
| `ci.no_runner_minutes` | `15` | A queued job whose labels no registered runner has fails after this long |
| `mcp.enabled` | `false` | The connector. Set by `CODEHAVEN_MCP_ENABLED` |
| `mcp.trusted_client_hosts` | `["claude.ai"]` | Hosts whose client documents the server will read |
| `mcp.allowed_origins` | `["https://claude.ai", "https://claude.com"]` | Browser origins allowed to call `/mcp` besides the instance's own |
| `workspace.enabled` | `true` | The ceiling for the browser editor. A site admin can turn it off, never on past this |
| `workspace.terminal` | `true` | The same for the browser terminal |
| `server.docs_url` | the public docs site | Set by `CODEHAVEN_DOCS_URL` |
| `pages.host` | empty | Set by `CODEHAVEN_PAGES_HOST` |
| `pages.max_files`, `pages.max_bytes` | `2000`, 50 MiB | The largest published copy of a site |
| `pages.reply_stall_secs`, `pages.reply_deadline_secs`, `pages.replies_per_address` | `60`, `600`, `32` | Limits on Pages replies: a reply that sends nothing for the stall time is cut, none takes longer than the deadline, and one client address may hold this many open |
| `log.format`, `log.level` | `json`, `info` | `json` or `pretty`; the level is a `tracing` filter such as `info` or `ch_git=debug` |

`public_access.*` holds the limits for signed-out visitors, per client address (an IPv6 address counts by its /64) and for the whole instance. Every value must be more than 0 and an instance cap may not be below its per-address cap, or the server refuses to start. The defaults are `requests_per_minute` 240, `burst` 120, `instance_requests_per_minute` 600, `lookups_at_once` 8, `heavy_per_address` 2, `heavy_instance` 4 (blame, compare, diffs and recursive trees), `git_per_address` 2, `git_instance` 3, `git_per_address_per_minute` 30, `git_timeout_secs` 600 (clones and fetches), `archive_per_address` 1, `archive_instance` 2, `archive_per_address_per_minute` 6, `archive_timeout_secs` 120 (zip and tar archives), `raw_per_address` 4 and `raw_instance` 10 (raw files, blobs and release files).

The compose file also fixes things you cannot set from the env file: the server and the database are each limited to 2 GB of memory, and the server's open file limit is 65,536.

## The runner's settings

The runner reads `deploy/runner.toml`, mounted into its container. Every key is optional, and an unknown key is an error so a typo never does nothing silently. `deploy/runner.example.toml` documents each key. `haven-runner check` reads the file and says what is wrong with it.

| Key | Stack value (default) | What it does |
| --- | --- | --- |
| `runner.work_dir` | `/work` | Where job directories live. Jobs mount it at the same path, so it must be the same inside the job daemon |
| `runner.concurrency` | `2` (2) | Jobs at once |
| `runner.poll_wait_seconds` | (30) | How long one job request waits at the server. The server caps it at 30 |
| `runner.shutdown_grace_seconds` | `90` (60) | On stop, running jobs get this long to finish, then they are cancelled |
| `runner.debug` | (false) | Show `::debug::` lines in logs |
| `limits.cpus`, `limits.memory`, `limits.pids` | `4`, `8g`, `4096` | Per job container. A workflow's `container.options` may ask for less, never more |
| `limits.shm_size` | (`1g`) | Shared memory per job |
| `limits.max_job_minutes` | `360` (360) | No job runs longer than this, whatever its own `timeout-minutes` says |
| `limits.max_log_megabytes` | (100) | A job's log stops growing after this, and says so |
| `limits.service_wait_seconds` | (120) | How long a `services:` container gets to take connections |
| `disk.guard_paths`, `disk.max_percent` | `["/work", "/dind-data"]`, `85` | Disks checked before each job. Over the percent, the runner prunes images, and if that is not enough it stops taking jobs |
| `docker.pull_policy` | `if-not-present` | Or `always` |
| `docker.prune_after_days`, `docker.prune_interval_minutes` | `7`, (60) | Unused images older than this are removed. Images named under `[labels]` are never removed |
| `labels` | `ubuntu-latest`, `ubuntu-24.04`, `linux` | Which image a job runs in: the first label of its `runs-on` that is listed. Every label here runs `codehaven-job:trixie`. Listing a `[labels]` table replaces the built-in one |

After editing it, recreate the runner: `sudo bash deploy/prod/ci-up.sh`.
